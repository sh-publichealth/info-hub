## Obtain the live event map

Use the latest existing raw export; no patient data need to be sent back:

```stata
do "scripts/stata/tmr/monitoring/tmr-visit-map-audit-v1.do" ///
    "C:/yoshimi-hot/output/analyse-sth/sh007-total-meal-replacement/stata" ///
    "C:/yoshimi-hot/output/analyse-sth/sh003-diabetes-registry/info-hub/scripts/stata/tmr/monitoring/config/tmr-visit-map-draft.csv"
```

This creates a **new draft** with observed measurement event names and repeat-instance numbers. It will not overwrite an existing draft. Complete it using REDCap's Define My Events and repeating-event/instrument configuration, then save it as `config/tmr-visit-map.csv`. The draft lists event/instance names only, not participant identifiers or measurements. Event combinations introduced later must also be mapped.

CSV columns:

| Column | Meaning |
|---|---|
| `redcap_event_name` | Exact exported REDCap event name |
| `repeat_instance` | Exported instance number; use 0 for a non-repeating row |
| `planned_visit` | Scheduled code 1–20 below; 0 for an optional visit |
| `display_order` | Equal to the scheduled code; for optional visits use a noninteger position between the surrounding planned rows |
| `visit_label` | Explicit visit name; for optional visits include an additional-visit description |

Scheduled codes:

| Codes | Visits |
|---|---|
| 1 | Baseline |
| 2–7 | TMR visits 1–6 |
| 8–11 | Food visits 1–4 |
| 12–16 | Year 1 weight visits 1–5 |
| 17–20 | Year 2 weight visits 1–4 |

For example, an optional visit after TMR visit 4 (code 5) and before TMR visit 5 (code 6) could have `planned_visit=0`, `display_order=5.1`. A second additional visit could use 5.2. These are ordering instructions, not elapsed weeks. Use the participant's actual dates to display timing. If an optional event occurs in different phases for different participants, a single event-level display order is insufficient: supply the event configuration for review before using that map.

Each CSV key (`redcap_event_name`, `repeat_instance`) must be unique. Multiple instrument rows belonging to one scheduled visit may map to the same planned code, provided their core measurement dates and observed outcome values agree. Multiple actual core visits within one planned code stop with a conflict; assign the additional visits their own optional identities. Repeated instruments whose instance numbering does not represent visits require careful mapping against the actual REDCap configuration.

Unmapped measurement rows stop with a visible list; the scripts never infer TMR visit 6 from the seventh recorded date, elapsed time, or the presence of HbA1c.

## Reporting rules

- Each logical scheduled or optional visit contributes once. Complementary instrument rows are consolidated. Conflicting weight, HbA1c, diabetes medication or core visit dates stop preparation, rather than being averaged or selected silently.
- Baseline comes from the mapped baseline event. A later first-observed HbA1c or medication value is not substituted for a missing baseline.
- Group summaries use scheduled visits; optional visits remain on participant pages and actual-time graphs. The existing graph calculations are otherwise preserved.
- Participant tables retain the original 15 planned rows, insert that person's optional visits, and extend to later scheduled visits when observed. Dates accompany visit labels. Tables can flow onto another page; review pagination in the synthetic run.
- Medication cells show the full original value label. Missing values stay blank. Nothing is carried forward.
- Group medication cells show category counts and their own denominator, not a mean of the response codes. “No medication” and “stopped medication” both count as 0; oral and injectable monotherapy both count as 1; the highest group remains 3+.
- Paired comparisons include only participants with baseline and TMR-6 medication observations. They detect category changes, not changes within 3+ or route changes within monotherapy.
- Withdrawal-point descriptions use the last actual dated visit on or before withdrawal, including optional visits.
